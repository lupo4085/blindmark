# V3-7 读不回就算没完成；加水印也能申请可信时间戳

- **基线分支**：`main`（`983ae8b`），工作分支 `t-v3-7`
- **预计**：M（约 300 行，含测试）
- **范围**：`src/lib.rs`、`src/distribute.rs`、`src/jobs.rs`、`src/timestamp.rs`（只加共用的清单辅助函数和改帮助文字）、`src/bin/cli.rs`；`src/win/start.rs`、`src/win/embed.rs` **只允许**为编译通过补 `tsa: None` 之类的新字段，不改任何界面行为。
- **背景**：W-5 走查时，纯黑图加水印后显示“已加上水印”“成功 1 张”。V3-6c 的做法是读不回也照样保存、登记，再附一条提醒，这个做法本身是错的：用户拿到一份没有保护作用的副本，界面还说成功了。另外，时间戳只有分发能用，单独加水印不能用。界面怎么显示由 W-5b/W-5c 做，本卡只改核心和命令行。

## 1. 读不回 = 没有完成
在 `src/lib.rs` 新增：
```rust
/// The watermark could not be read back from the saved file: the picture is too flat
/// (large pure black / white areas). The output was deleted and nothing was registered.
#[derive(Debug)]
pub struct WatermarkNotReadable { pub file: String }   // file = 输入文件名
// Display（英文，命令行直接用）：
// "{file}: the picture is too flat (large pure black or white areas) to hold a watermark; it could not be read back, so nothing was saved."
impl std::error::Error for WatermarkNotReadable {}
```
`embed_file`（以及第 2 节的 `embed_file_with`）和 `distribute::make_copy` 的顺序改为：
1. 保存 → 读回算 `sha256_file` → `check_embedded`
2. 结果是 `Unreadable`：**删除刚写的输出文件**（删除失败忽略），**不登记**，返回 `Err(anyhow::Error::new(WatermarkNotReadable { file }))`。
3. `check_embedded` 本身返回 `Err`（比如读回失败）：同样删除输出文件、不登记，返回这个错误，外面加 context `could not read back the saved file`。
4. `Ok` 或 `Weak`：照常登记，返回成功。`EmbedCheck::Unreadable` 这个变体保留（序列化格式不变），但成功结果里不会再出现它。

分发：同一张图的某一份副本因 `WatermarkNotReadable` 失败后，这张图剩下的接收人**不再加水印**，直接各记一条同样类型的失败（`Start`/`Done` 回调照常发），节省时间。装不装得下水印由图片本身决定，结果不会不同。

`jobs::classify` 新增一个分支（放在最前面）：`downcast_ref::<WatermarkNotReadable>()` 命中时，message 照抄：
`{name} 大面积是纯色，装不下水印：加完以后读不回来，所以没有保存，也没有登记。换一张内容更丰富的图，或者裁掉纯色区域再试。`

## 2. 加水印批次和时间戳
- `lib.rs`：
  ```rust
  pub struct EmbedResult { pub id: u32, pub psnr: f64, pub check: EmbedCheck, pub sha256_file: String }
  pub fn embed_file_with(input, output, key, reg, strength, channel, jpeg_quality, batch_id: Option<&str>) -> Result<EmbedResult>;
  pub fn embed_file(...) -> Result<EmbedResult>   // 签名不变，= embed_file_with(..., None)
  ```
  `batch_id` 为 Some 时写进登记条目的 `CopyMeta.batch_id`。
- `jobs.rs`：
  - `EmbedJob` 加 `pub tsa: Option<String>`。
  - `EmbedOk` 加 `pub sha256_file: String`。
  - `EmbedEvent` 加 `Stamping`（开始联网申请时间戳之前发一次，不申请就不发）。
  - `EmbedSummary` 加 `pub batch_id: String` 和 `pub stamp: Option<Result<StampOk, UserError>>`。
  - `run_embed`：开头用 `distribute::batch_id_now()` 生成批次号，**每次都生成**，每张成功的图都用 `embed_file_with(..., Some(&batch_id))` 登记。全部结束后（包括被停止）：`tsa` 有值并且至少一张成功时，发 `Stamping`，用成功的图生成清单并调用 `timestamp::stamp_batch`；结果用 `run_distribute` 现有的同一套转换（`stamp_file_error`、`stamp_ok`）放进 `summary.stamp`。时间戳失败不影响已经保存的图片。
  - 清单：`ManifestCopy { id: "0x{:08x}", recipient_id: None, recipient_name: None, source: 输入文件名, sha256_file, check: Some(check) }`。生成 `Manifest` 的代码和分发**共用一个辅助函数**（放在 `timestamp.rs`，例如 `Manifest::new(batch_id, key, copies)`，填 format、created_utc、key_fingerprint），分发改为调用它，不要复制粘贴。
  - 重试：现有的 `jobs::retry_stamp` 对加水印批次同样适用，不用改。
- `timestamp.rs`：`stamp list` / `stamp retry` 相关的帮助文字、注释里“distribution batches”改成不限于分发的说法（例如 “batches (watermarking or distribution)”）。

## 3. 命令行
- 普通 `embed`（不带 `--to`）改为调用 `jobs::run_embed`，不再直接调用 `embed_file`：
  - 修掉现有 bug：现在输出名固定为 `{stem}_wm.ext`，会覆盖已有文件。改走 `run_embed` 以后由 `unique_output_path` 保证不覆盖。
  - `--timestamp` / `--tsa` 对普通 embed 也生效（`tsa: timestamp.then(|| tsa.clone())`）。帮助文字改为 “Request an RFC 3161 timestamp for this batch (off by default).”（去掉只针对分发的说法，如果有）。
  - 每张成功的图输出一行 JSON：`{"input","output","id","psnr_db","check","sha256_file","sec"}`（`sec` 保持现在的含义：从开始到这张完成的累计秒数）。
  - 失败的图在 stderr 打印一行：`error: {UserError.message 对应的英文}` 不好做时，直接打印 `error: {input}: {原始错误}`；`WatermarkNotReadable` 的 Display 本身就是英文说明，原样打印。
  - 最后输出一行汇总 JSON（和分发一样）：`{"batch_id","ok","failed","stamp":"ok"|"failed"|null}`。
  - stderr 汇总：`{w} weak, {f} failed`，两个都为 0 时不打印（替代原来的 `{n} weak, {m} unreadable`）。
  - 退出码保持不变（0）。
- 分发（`--to`）：stderr 汇总同样改成 `{w} weak, {f} failed`；读不回的副本现在会走失败路径。

## 4. 测试
- `embed_file` 对纯黑图（720×1600，底部 60 行噪声，同 V3-6c 的测试图）：返回的错误能 downcast 成 `WatermarkNotReadable`；输出文件不存在；登记表条目数不变。
- 有纹理的图：成功，`sha256_file` 等于磁盘文件实际哈希。
- 分发：纯黑图 × 3 人 → `copies` 为空，`failed` 3 条都是 `WatermarkNotReadable`；输出目录里没有这张图的任何文件；登记表 0 条。再加一张正常图一起分发（2 图 × 3 人）→ 3 成功、3 失败。
- `run_embed`：`tsa: None` → `summary.stamp` 为 None，没有 `Stamping` 事件，`batch_id` 以 `b_` 开头，成功条目的 `batch_id` 等于它，登记表文件夹里没有 `timestamps/`。
- `run_embed`：`tsa: Some("http://127.0.0.1:9/tsr")`（本机不监听的端口，连接立即被拒，不会真的联网）→ 收到一次 `Stamping`，`summary.stamp` 是 `Some(Err(..))`，message 是 V3-4 的 Network 文案；图片仍然保存、登记。全部失败时（只有纯黑图）不发 `Stamping`，`stamp` 为 None。
- 清单辅助函数：分发和加水印生成的 `Manifest` 字段一致（format、key_fingerprint）。
- 命令行：同一个输出文件夹连续 `embed` 同一张图两次 → 两个不同的输出文件，第一个内容不变。
