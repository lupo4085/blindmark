## 样本内容
密钥统一用 `key = (0u8..32).collect::<Vec<u8>>()`，和 `keys.rs` 里现有测试一致。

| 文件 | 内容 | 怎么来 |
|---|---|---|
| `tests/golden/cover.png` | 320×256 的合成图：横向渐变 + 用固定种子（`0x5EED`）生成的块状噪声 + 几条斜线。**不用任何外部图片** | 生成器写出 |
| `tests/golden/marked.png` | `cover.png` 用上面的密钥、编号 `0x0BADF00D`、强度 2.6 加水印的结果 | 生成器写出 |
| `tests/golden/registry-v02/` | 一个 v0.2 格式的登记表：`registry.json`、`meta.json`、一张缩略图。条目里**没有** recipient 等新字段 | 用 **main 分支 v0.2 时的代码**生成：`git stash`/新工作树切到 tag 或提交 `7eb5863`，用 CLI 对 `cover.png` 加一次水印，把登记表目录拷过来 |
| `tests/golden/recipients-v1.json` | alpha 格式的接收人簿：1 个一级分组、1 个子分组、2 个人，ID 用旧格式 `g_0001`、`r_0001` | 手写 |
| `tests/golden/README.md` | 说明每个文件的来历，以及**禁止为了让测试通过而重新生成样本** | 手写 |

生成器放在 `examples/make_golden.rs`，运行 `cargo run --release --example make_golden` 会覆盖写出 `cover.png` 和 `marked.png`。**它只在第一次建样本时运行一次**，之后不再运行。

## 测试（`tests/golden.rs`）
1. `marked_is_detected`：读 `marked.png`，用 `detect_image_opts`（默认选项，无登记表）检测，必须 `found == true`、编号 `0x0BADF00D`、`method == "crc"`。
2. `embed_is_stable`：对 `cover.png` 重新加水印（同一密钥、编号、强度），和 `marked.png` 逐像素比较，每个通道的差值都不超过 1。
3. `cover_is_clean`：检测 `cover.png`，必须 `found == false`。
4. `registry_v02_loads`：以只读方式打开 `registry-v02/` 的一份**临时拷贝**，条目数为 1，`check_key` 通过。
5. `recipients_v1_loads`：把 `recipients-v1.json` 拷到临时目录改名为 `recipients.json`，`Book::open` 成功，能按旧 ID 找到人和分组。
6. `keys_vectors`：把 `keys.rs` 里现有的 Python 测试向量再断言一遍（可以直接调用同样的函数），作为格式冻结的第二道保险。

## 自检脚本
`scripts/check.ps1`（Windows）和 `scripts/check.sh`（Linux/macOS）做同样的事，任何一步失败就停下并返回非零：
1. `cargo test --release --lib`
2. `cargo test --release --test golden`
3. Windows 上 `cargo build --release --bins`；其他平台 `cargo check --features win32-check --bins`
4. 如果能找到 `python3`（或 `python`）并且能 `import cv2, numpy`：用 Python 参考实现检测 `tests/golden/marked.png`，编号必须一致。找不到 Python 时打印“跳过 Python 互通测试”，不算失败。

脚本最后一行打印 `ALL CHECKS PASSED`。

## 不要做

- 不要运行 `cargo fmt`。
