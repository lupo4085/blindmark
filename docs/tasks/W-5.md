# W-5 向导分发流程 D1–D5，主窗口入口

- **基线分支**：`t-v3-4` 合并后的 `main`，工作分支 `t-w-5`
- **预计**：L（界面卡，diff 允许到 700 行）
- **先读**：`docs/tasks/W-COMMON.md`、`docs/specs/wizard.md` 第 4、8 节、`docs/specs/ui-copy.md` 第三节的 D 部分和**第五节**
- **范围**：`src/win/start.rs`、`src/win/recdlg.rs`（新建）、`src/win/embed.rs`（只加按钮）、`src/win/mod.rs`（只改 `open_start` 和按钮处理）、`src/win/config.rs`（只加 `tsa_url`）、`assets/blindmark.rc.in`
- **不做**：编辑、归档、重命名分组、显示已归档（W-6 做）；登记表页和检测页的接收人列（W-6 做）

alpha 分支的 `distdialog.rs` **不搬过来**，可以参考它的列表和勾选写法，但流程以本卡为准。

## 1. 设置
`Settings` 加 `pub tsa_url: String`，`#[serde(default = ...)]` 默认 `blindmark::timestamp::DEFAULT_TSA`。旧的 settings.json 里如果有 alpha 留下的 `"timestamp": true`，忽略它（确认 `Settings` 没有 `deny_unknown_fields`）。

## 2. 入口
- `WizardContext` 加 `pub start_task: Option<Task>`。`open_start`（F1 和启动弹出）传 `None`。
- “加水印”选项卡新增按钮「分发给多人…」，放在「开始加水印」左边，布局跟着 `embed::layout` 走。点了以后调用 `App::open_start_with(Some(Task::Distribute))`（在 `open_start` 基础上加参数，不要复制一份）。
- `start_task == Some(Distribute)`：`St.task = Distribute`，`prefix_setup = key.is_none()`；把 PROPSHEETHEADER 的 `nStartPage` 设成 D1（没有密钥时是 S1）在 `pages` 列表里的下标（不要用 `PSH_USEPSTARTPAGE`）。`history` 为空，所以起始页上“上一步”禁用。

## 3. 状态（加到 St）
```rust
d_files: Vec<PathBuf>,                 // 初始值 = ctx.embed_files
d_book: Option<blindmark::recipients::Book>,   // 进入 D2 时打开；打开失败记下错误文字
d_book_err: Option<String>,
d_checked: BTreeSet<String>,           // 勾选的接收人 ID。切换分组、刷新名单都不清空
d_filter: GroupSel,                    // enum GroupSel { All, Ungrouped, Group(String) }，默认 All
d_out_dir: String,                     // 默认 cfg.out_dir；为空时取 d_files[0] 的父目录（进入 D3 时计算）
d_per_dir: bool,                       // 默认 true
d_jpeg: bool, d_strength: f32,         // 默认取 cfg
d_stamp: bool,                         // 默认 false，每次打开向导都是 false
d_run: Option<RunState>,               // 和 E3 同样的结构，消息类型换成 DistEvent
d_results: Vec<DistRow>,               // struct DistRow { recipient: String, file: String, result: Result<DistItemOk, UserError> }
d_summary: Option<DistSummary>,
```
接收人名单的路径：`ctx.cfg.registry_dir`。如果是首次设置流程刚写的，用 S2 提交后的新路径（St 里已有）。

## 4. 页面
页面模板 250–254 照抄 230 的写法。跳转：选择任务页的“分发”→ 有密钥 250，没有 220；S2 提交后 task 是 Distribute 时去 250；其余按 W-COMMON。

**D1（250）**：和 E1 完全一样（同一套代码，按 task 换标题文字），列表数据用 `d_files`。如果 E1 的实现写死了 `files` 字段，抽一个以字段引用为参数的辅助函数，两边共用，不要复制粘贴整段。

**D2（251）**——线框（单位：对话框单位，按现有 `Lay` 排版）：
```
┌ 标题：选择要发给谁 ───────────────────────────────────────┐
│ 第 2 步，共 4 步 · 每位接收人都会拿到一份编号不同的副本      │
│ ┌TreeView 宽 30%──────┐ ┌ListView（复选框）宽 70%─────────┐ │
│ │全部接收人           │ │□ 接收人   │ 分组      │ 备注     │ │
│ │ 未分组              │ │□ 张三     │ 客户/秋季 │ 约稿     │ │
│ │ 客户                │ │                                  │ │
│ │   2026 秋季         │ │   （空状态文字居中显示）         │ │
│ └─────────────────────┘ └──────────────────────────────────┘ │
│ [新建分组…]               [新建接收人…]                     │
│ 已选 3 人 × 2 张图片 = 将生成 6 份                (红字错误) │
└──────────────────────────────────────────────────────────────┘
```
- 树：第一项“全部接收人”，第二项“未分组”，然后 `book.groups_tree()`，一级分组下挂子分组，全部展开。
- 名单：`book.list(filter, false)`。勾选状态完全由 `d_checked` 决定：每次重新填充名单时按 `d_checked` 设勾；用户点复选框（`LVN_ITEMCHANGED` 里状态图标变化）时更新 `d_checked`。**刷新名单时要先屏蔽这个通知，避免误改 `d_checked`。**
- 汇总行：`k = d_checked.len()`，`m = d_files.len()`，`n = k × m`，每次 `d_checked` 变化时更新。
- 「新建接收人…」：打开对话框 260（见第 5 节），分组下拉框默认选中当前树上选中的分组（选“全部接收人”或“未分组”时默认“未分组”）。成功后：`book.add_recipient`，新 ID 加进 `d_checked`，刷新名单。
- 「新建分组…」：打开对话框 261，上级分组下拉框默认是当前选中的一级分组（选中子分组时默认它的父分组；其他情况默认“无”）。成功后刷新树，并选中新分组。
- 名单打不开（`d_book_err`）：树和名单都清空并禁用，在汇总行位置显示红字（ui-copy 第五节），“下一步”时停在本页。
- 点“下一步”：`d_checked` 为空时红字“请至少选择一位接收人。”并停留。

**D3（252，提交页）**：控件按 ui-copy 第三节 D3：保存到（输入框 +「浏览…」，选文件夹）、两个单选项、格式（同 E2，包括“显示高级选项”和强度滑块，代码与 E2 共用）、时间戳复选框和说明（`{host}` 用 `timestamp::host_of(&cfg.tsa_url)`）。提交按钮文字“生成 {n} 份”，n 实时计算。保存位置为空时红字“请选择输出文件夹。”并停留。所有改动只存在 St 里。

**D4（253，进度页）**：照 E3 的写法。后台线程调用 `jobs::run_distribute`，`tsa = d_stamp.then(|| cfg.tsa_url.clone())`。收到 `Running` 更新进度文字，收到 `Item` 进度条加一格并存进 `d_results`，收到 `Stamping` 时进度文字改成“正在申请可信时间戳…”。`run_distribute` 返回 Err 时：所有组合都记成这个错误，照常进入 D5。停止确认框照 W-COMMON。

**D5（254，完成页）**：
- 标题三种情况见 ui-copy 第五节。`k = summary.recipients`。
- 结果 ListView 三列：接收人、图片、结果。
- 时间戳行：没勾选时隐藏。失败时旁边显示「重试」：点了以后按钮禁用、文字改“正在重试…”，**在后台线程**调用 `jobs::retry_stamp`，结束后更新这一行（成功就隐藏「重试」）。
- 「打开输出文件夹」打开 `d_out_dir`；「在登记表中查看」返回 `ShowInRegistry(所有成功的编号)`；「转到“加水印”选项卡」。没有任何一份成功时，前两个按钮禁用。

## 5. 两个小对话框（`src/win/recdlg.rs`）
用资源模板 + `DialogBoxParamW`，控件位置直接写在 `.rc` 里（对话框单位），**不在运行时排版**。
```rust
pub struct RecipientForm { pub name: String, pub group: Option<String>, pub note: String }
pub fn recipient_dialog(owner: HWND, title: &str, ok_text: &str, groups: &[(Option<String>, String)], init: RecipientForm) -> Option<RecipientForm>
pub fn group_dialog(owner: HWND, title: &str, ok_text: &str, parents: &[(Option<String>, String)], init_name: &str, init_parent: Option<String>, show_parent: bool) -> Option<(String, Option<String>)>
```
- 260 接收人：姓名（编辑框）、分组（下拉列表，第一项“未分组”，其余为“一级”或“一级 / 子级”）、备注（编辑框，可选）、确定按钮、取消按钮。宽 220、高 110 左右。
- 261 分组：名称、上级分组（第一项“无（作为一级分组）”，只列一级分组）。`show_parent = false` 时隐藏上级分组那一行（W-6 的重命名会用到）。
- 点确定时先在对话框里校验：姓名或名称为空 → 在按钮上方红字显示 ui-copy 的错误，不关闭。`Book` 返回的错误（比如“分组最多两级。”）由调用者处理：调用者拿到表单后调用 `Book`，失败就用同样的表单值**重新打开**对话框，并把错误文字传进去显示（给两个函数加一个 `error: Option<&str>` 参数）。
- 对话框过程同样要用 `guard` 包住。Esc 和 ✕ 等同取消。
