## 接口（照这个写，签名不许改）
```rust
// src/jobs.rs
use std::path::{Path, PathBuf};
use std::sync::atomic::AtomicBool;

#[derive(Clone, Debug)]
pub struct UserError {
    pub message: String, // 中文一句话，文案见 docs/specs/ui-copy.md 第二节
    pub detail: String,  // 原始错误（format!("{e:#}")）
}
impl std::fmt::Display for UserError { /* 只输出 message */ }

/// 打开登记表，准备写入。会先比较指纹，不配对时返回 Err，并且不写任何文件。
pub fn open_registry_for_write(dir: &Path, key: &[u8]) -> Result<crate::registry::Registry, UserError>;

#[derive(Clone, Debug)]
pub struct EmbedJob {
    pub files: Vec<PathBuf>,
    pub out_dir: Option<PathBuf>, // None 表示输出到原图所在的文件夹
    pub suffix: String,
    pub strength: f32,
    pub jpeg_quality: Option<u8>, // None 表示输出 PNG
    pub channel: Option<String>,
}
#[derive(Clone, Debug)]
pub struct EmbedOk { pub id: u32, pub psnr: f64, pub output: PathBuf }
#[derive(Clone, Debug)]
pub enum EmbedEvent {
    Running { index: usize },
    Item { index: usize, result: Result<EmbedOk, UserError> },
}
#[derive(Clone, Debug, Default)]
pub struct EmbedSummary { pub ok: usize, pub failed: usize, pub cancelled: bool }

/// 按顺序处理 job.files。只有登记表打不开或者不配对时才返回 Err，这种情况下一张都不处理。
/// 每处理一张之前检查一次 cancel。
pub fn run_embed(job: &EmbedJob, key: &[u8], registry_dir: &Path, cancel: &AtomicBool,
                 on_event: &mut dyn FnMut(EmbedEvent)) -> Result<EmbedSummary, UserError>;

pub struct DetectContext { /* 私有字段：Option<Registry>、Option<wm::KnownIds> */ }
pub struct DetectResult { pub report: crate::Report, pub entry: Option<crate::registry::Entry> }
impl DetectContext {
    /// registry_dir 为 None 时不使用登记表。登记表和密钥不配对时返回 Err。
    pub fn open(registry_dir: Option<&Path>, key: &[u8]) -> Result<DetectContext, UserError>;
    pub fn registry(&self) -> Option<&crate::registry::Registry>;
    /// entry 是检出编号（或者通过画面定位到的编号）在登记表里对应的那条记录。
    pub fn detect(&self, img: &crate::registry::RgbImageBuf, key: &[u8],
                  thumbs: Option<&crate::registry::ThumbIndex>, opts: &crate::DetectOptions) -> DetectResult;
}
```

## 实现要点
1. **判断是否配对**：用 `keys::fingerprint(key)` 和 `registry.meta` 里的 `key_fingerprint` 比较，不一致时返回“登记表和密钥不配对”那条文案，`{fp}` 填登记表的指纹。如果 `meta` 是 None，就交给 `check_key` 去写入。**不要靠解析错误字符串来判断。**
2. **单张图片出错时的分类**，写成私有函数 `classify(e: &anyhow::Error, name: &str, out_dir: &Path) -> UserError`：
   - 错误链里有 `image::ImageError::Decoding` 或 `Unsupported`：用“图片打不开”那条
   - 错误链里有 `std::io::Error`，并且类型是 `PermissionDenied`，或者是写文件时出的错：用“输出文件夹不可写”那条
   - 其他情况：用“其他意外错误”那条
   - 三种情况的 `detail` 都填 `format!("{e:#}")`
3. **输出路径**：沿用现在的规则：`unique_output_path(dir, path, suffix, jpeg)`，`dir` 是 `out_dir` 或者原图所在的文件夹。
4. 主窗口 `embed.rs`：后台线程里改为调用 `run_embed`，`index` 对应回原来的 `row`。`WorkerMsg::EmbedItem` 的 `res` 类型改成 `Result<EmbedOk, UserError>`。`on_item` 失败时显示 `✗ {message}`，`detail` 用 `eprintln!` 输出。成功时的显示保持不变，PSNR 等文字留到之后整体改文案时再处理。
5. 主窗口 `detect.rs`：后台线程里改为 `DetectContext::open(...)` 加 `ctx.detect(...)`。行为保持不变：只有 `a.reg.is_some()` 时才传入登记表目录。

## 测试（写在 src/jobs.rs 的 `#[cfg(test)]` 里，Linux 上要能跑）
用临时目录。测试图片用 `image` crate 生成一张 512×512、带纹理的 PNG，不要用纯色图。
- [ ] `embed_two_files`：处理 2 张 → `ok == 2`，登记表里有 2 条，2 个输出文件都存在，`on_event` 收到 2 个 Running 和 2 个 Item
- [ ] `wrong_key_is_rejected`：用密钥 A 建好登记表，再用密钥 B 调用 `run_embed` → 返回 Err，`message` 里包含“另一把密钥”，登记表条数仍然是 0，输出目录里没有新文件

- [ ] `bad_image_is_reported`：一个内容是文本的 `x.png` → 这一项是 Err，`message` 以“无法打开 x.png”开头；其他图片照常处理
