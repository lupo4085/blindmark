## 背景（Claude 对 calib.csv 的分析结论）

1. 在 523 张未加水印的图上做了 15,690 次检测，`z_sync` 最大 6.99，有 9 次 ≥ 6.5。阈值放在负无穷时，CRC 和登记表匹配**一次都没有通过**，所以“认成你的图片”这类误报是 0。现在的 6.5 加上 CRC 或登记表这一道关，已经足够安全。
2. 但如果 `z_sync ≥ 6.5`，CRC 却没通过，界面会显示“可能有你的水印，但读不出编号”。这句提示的误报率约为 6×10⁻⁴，**太高了**。加了水印、能读出编号的图，`z_sync` 最低是 10.1。
3. **严重问题：登记表匹配会认错编号。** 160 次正样本检测里，有 5 次走了登记表匹配，返回的编号不对：这几张图的真实编号并不在测试用的登记表里，程序却从 1000 个随机编号中挑了一个当结果。原因是现在的阈值只在“图里没有水印”时成立。图里有同一把密钥的真实水印时，任何一个随机编号都能和它对上大约一半的位，得分很容易超过阈值，而 `hamming ≤ 16` 这个条件对 1000 个编号来说太宽松：随机编号碰巧满足的期望个数约为 15 个。

## 设计

### 1. 登记表匹配：汉明距离上限随登记表大小变化（`wm.rs`）

新增：
```rust
/// Per-check false-match budget for registry matching.
pub const REGISTRY_FP: f64 = 1e-6;

/// Largest k such that n_ids * P(Binomial(NBITS, 1/2) <= k) <= REGISTRY_FP.
/// None if even k = 0 exceeds the budget (registry too large to match safely).
pub fn registry_max_hamming(n_ids: usize) -> Option<usize>
```
用 f64 精确计算二项分布的累积概率：`C(48, i) / 2^48` 逐项累加，C 用递推 `C(n, i+1) = C(n, i)·(n−i)/(i+1)`，不加依赖。

依据：一个错误编号的 48 位和图里真实的 48 位互相独立，所以无论图里有没有水印，错误编号和读出位之间的汉明距离都服从 Binomial(48, ½)。这个上限对两种情况都成立。

`finish` 里的登记表分支改成：
- `hamming <= NBITS / 3` 改为 `Some(k) = registry_max_hamming(ids.len())` 且 `hamming <= k`
- `best >= thr` 保留
- 新增条件：除了最佳编号，**不能再有第二个编号**满足 `hamming <= k`。有两个以上就当作没匹配上，返回 `found: false`

### 2. 只有分数、没有编号时，“可能有水印”的门槛提高到 8.0（`wm.rs`）

新增：
```rust
/// Without a decoded ID, report "watermark probably present" only above this sync score.
/// Calibrated in V3-6: max over 15,480 unmarked checks was 6.99; min over identified marked copies was 10.1.
pub const Z_PRESENT_ONLY: f64 = 8.0;
```
`finish` 的规则：
- 解码和登记表匹配的门槛照旧：`z >= z_thresh`
- `found == true` 时：`present = true`
- `found == false` 时：`present = z >= z_thresh.max(Z_PRESENT_ONLY)`

其他地方不改。严格模式（7.5）同样适用这条规则。

### 3. 标定程序：正样本的登记表包含真实编号（`examples/calibrate.rs`）

- 正样本的 `KnownIds`：用 `registry_ids(1000 + pi, n)` 生成后，把**下标 `pi % n` 处的编号替换成真实编号 `pid`**。
- CSV 在最后加一列 `id_ok`：正样本里 `found` 且编号等于 `pid` 时为 `1`，`found` 但编号不对时为 `0`，没找到时为空；负样本一律为空。`--resume` 读旧文件时，缺少这一列也要能读。
- 新增参数 `--skip-negatives`：只跑正样本。
- `calib_report.py`：正样本部分加一行“认错编号（id_ok = 0）的次数”。没有 `id_ok` 列时跳过这一行。

## 测试（加在 `wm.rs` 的 tests 里）

- `registry_max_hamming(1000) == Some(4)`，`(10_000) == Some(3)`，`(100_000) == Some(2)`，`(1) == Some(7)`
- **认错编号回归测试**：用 `encode_payload(key, A)` 的位构造 `soft`（位为 1 取 +10，为 0 取 −10），翻转 3 位让 CRC 失败。登记表是 1000 个随机编号、不含 A 时，`finish(z = 20.0, …)` 必须 `found == false`；把 A 放进登记表后，必须 `found == true` 且编号是 A。
- **present 门槛**：同样构造，但不传登记表。z = 7.0 时 `present == false`，z = 8.5 时 `present == true`，两种情况 `found` 都是 `false`。
- 不翻转位（CRC 通过）、z = 6.6 时：`found == true`，`present == true`
