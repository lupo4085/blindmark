## 设计
密钥文件里是 32 字节随机数的十六进制文本。BIP39 的 24 个词正好编码 32 字节（256 位熵 + 8 位校验），所以**助记词就是密钥本身的另一种写法**，不是派生出来的。恢复以后得到的密钥和原来逐字节相同，指纹也相同，旧水印照常能读。

- 依赖：`bip39 = "3"`（CC0-1.0 许可证，rust-bitcoin 维护）。只用英文词表，不开 `all-languages`。
- 加依赖后检查“关于 → 许可证…”里的第三方列表能列出 bip39 和它新带进来的依赖（`build.rs` 自动生成，正常情况下不用改）。如果 `build.rs` 不认识 `CC0-1.0`，在审阅包里提问，不要自己改 `build.rs`。

## 接口（照写）
```rust
// keys.rs
#[derive(Debug, PartialEq)]
pub enum WordsError {
    WrongLength(usize),        // 密钥不是 32 字节，无法用助记词表示
    WordCount(usize),          // 输入的词数不是 24
    UnknownWord(usize, String),// 第几个词（从 1 开始）、原词
    Checksum,                  // 词都认识，但校验对不上（通常是顺序错了或抄错了一个词）
}
pub fn key_to_words(key: &[u8]) -> Result<Vec<String>, WordsError>;
pub fn key_from_words(text: &str) -> Result<[u8; 32], WordsError>;
/// 按下面的规范化规则数词，给界面的实时计数用。
pub fn count_words(text: &str) -> usize;
```
`key_from_words` 先规范化输入：转小写；所有空白（含换行、全角空格 U+3000）当分隔符；去掉每个词前面的 `1.`、`1)`、`1、` 这类序号（这样用户把显示出来的带序号文本整段粘回来也能识别）；空词丢弃。然后：
1. 词数不是 24 → `WordCount(n)`
2. 用 `bip39::Language::English.find_word` 逐个查，找不到 → `UnknownWord(i, 原词)`
3. `bip39::Mnemonic::parse_in_normalized(Language::English, &joined)`，校验失败 → `Checksum`

```rust
// jobs.rs
pub fn key_words(key: &[u8]) -> Result<Vec<String>, UserError>;
pub fn restore_key_file(text: &str, path: &Path) -> Result<Vec<u8>, UserError>;
pub fn write_key_bytes(key: &[u8; 32], path: &Path) -> Result<Vec<u8>, UserError>;
pub fn words_error_message(e: &keys::WordsError) -> String;
```
`write_key_bytes`：如果 `path` 已存在：内容是同一把密钥（指纹相同）→ 直接返回，不写文件；不同的密钥 → 报错，**绝不覆盖**。不存在 → 按 `create_key_file` 现有的写法写入（同样的权限和换行）。
`restore_key_file` = `key_from_words` + `write_key_bytes`。
`words_error_message` 把 `WordsError` 换成下表的 message，界面和 `UserError` 都用它，文案只写这一处。

`UserError.message` 原文：
| 情况 | message |
|---|---|
| WrongLength | 这把密钥不是标准长度，不能生成助记词。请直接备份密钥文件。 |
| WordCount(n) | 需要 24 个词，现在是 {n} 个。 |
| UnknownWord(i, w) | 第 {i} 个词“{w}”不在词表里，请检查拼写。 |
| Checksum | 这些词对不上校验，可能有一个词抄错了，或者顺序不对。请逐个核对。 |
| 目标位置已有另一把密钥 | 这里已经有另一把密钥（密钥指纹 {fp}），不会覆盖它。请换一个位置。 |

## 命令行
```
blindmark-cli key words   --key my.key          打印 24 个词，每行一个，带序号 "1. word"
blindmark-cli key restore --key new.key         从标准输入读取助记词（可以多行），写出密钥文件
```
- `key words` 在 stderr 先打印一行：`任何人拿到这 24 个词，就等于拿到了你的密钥。请抄在纸上，不要截图或发给别人。`
- `key restore` **不接受**把词写在命令行参数里（会留在 shell 历史里）。成功后打印 `restored <path> (fingerprint <fp>)`。

## 测试
- 固定向量：`key = 0..32` 的助记词必须是
  `abandon amount liar amount expire adjust cage candy arch gather drum bullet absurd math era live bid rhythm alien crouch range attend journey unaware`
- 往返：100 把随机密钥 → 词 → 密钥，逐字节相同
- 规范化：大写、多个空格、换行、全角空格、带 `1.`／`1)`／`1、` 序号的文本都能恢复
- 交换前两个词 → `Checksum`；把 `abandon` 写成 `abandom` → `UnknownWord(1, "abandom")`；23 个词 → `WordCount(23)`
- 16 字节的密钥 → `WrongLength(16)`
- `restore_key_file`：目标已有同一把密钥 → 成功且文件修改时间不变；已有另一把 → Err，文件内容不变
- `scripts/check` 全绿（黄金样本证明 `keys.rs` 原有行为没变）
