## 1. jobs.rs 新增（签名照抄）
```rust
pub enum RegistryStatus { New, Matches { entries: usize }, Mismatch { fingerprint: String } }
/// 只读检查：不创建文件夹，也不写任何文件。直接读 dir/meta.json 和 dir/registry.json；文件夹或文件不存在时返回 New。
pub fn inspect_registry(dir: &Path, key: Option<&[u8]>) -> Result<RegistryStatus, UserError>;
/// 新建密钥文件。目标已经存在时返回 Err，且绝不覆盖。会自动创建上级文件夹。文件内容是 hex 加换行，和 CLI keygen 生成的一样。
pub fn create_key_file(path: &Path) -> Result<Vec<u8>, UserError>;
/// 读取密钥文件。文件无效时返回 Err，文案用“{name} 不是 BlindMark 的密钥文件。”
pub fn read_key_file(path: &Path) -> Result<Vec<u8>, UserError>;
```
测试（写在 jobs.rs 里）：
- `inspect_new_dir_creates_nothing`：对一个不存在的文件夹调用 → 返回 New，调用后这个文件夹仍然不存在
- `inspect_detects_mismatch`：用 A 密钥建好登记表，再用 B 密钥检查 → 返回 Mismatch
- `create_key_refuses_overwrite`：同一个路径连续创建两次 → 第二次返回 Err，文件内容不变
- `read_key_rejects_garbage`：读一个内容乱写的文件 → 返回 Err，message 以文件名开头

## 2. St 新增字段
```rust
key_choice: KeyChoice,           // enum KeyChoice { New(PathBuf), Existing(Option<PathBuf>) }
registry_dir: PathBuf,
new_key: Option<Vec<u8>>,        // S2 提交时才生成
prefix_setup: bool,
created_key_path: Option<PathBuf>, // 本次新建了密钥时才有值；用于完成页上的备份按钮
```
`St` 创建时的初始值：`key_choice` 设为 `New(ctx.cfg.key_path，如果它是空的就用 app_dir()/blindmark.key)`；`registry_dir` 设为 `ctx.cfg.registry_dir`，如果它是空的就用 `app_dir()/registry`。

## 3. 页面
**S1（220）**
- 两个单选项。
- 选“新建”时：下面显示保存位置，旁边有「更改位置…」按钮（用 `save_file` 选位置，默认文件名 blindmark.key）。
- 选“使用已有”时：显示「浏览…」按钮；选好文件后显示路径和密钥指纹。文件无效就用红字提示。
- 红字提示的颜色用 `on_ctlcolor` 现有的警告色。
- PSN_WIZNEXT 时的检查：
  - 选“新建”且目标位置已存在：弹 TaskDialog，按钮为「使用这把密钥」和「换个位置」。选“使用这把密钥”，就把 `key_choice` 改成 `Existing(path)` 并继续往下走；选“换个位置”，就停在这一页（DWLP_MSGRESULT = -1）。
  - 选“使用已有”但还没选文件，或者文件无效：在页面内用红字提示，并停在这一页。
- **这一页不写任何文件。**

**S2（221）**
- 一个位置输入框，旁边是「浏览…」，下面一行显示状态。
- 页面进入时、以及输入框内容变化时（EN_CHANGE，加 300ms 防抖），调用 `inspect_registry` 刷新状态行。检查时用的密钥：选“已有”时用那把密钥；选“新建”时传 None，状态行只会显示“这是一个新的登记表”或者“已有登记表，共 N 条记录”（这时还没有密钥可以比较）。
- 提交（PSN_WIZNEXT）按下面的顺序执行，任何一步失败都在页面内用红字提示，并停在这一页：
  1. 拿到密钥：“新建”就调用 `create_key_file`，并记下 `created_key_path`；“已有”就调用 `read_key_file`。
  2. 再调用一次 `inspect_registry(dir, Some(key))`。结果是 Mismatch 就用红字提示并停下。注意：如果第 1 步刚新建了密钥，这时**不要删除它**，只提示用户换一个登记表文件夹。
  3. 调用 `jobs::open_registry_for_write(dir, key)`，它会负责初始化 meta.json。
  4. 设置 `outcome = SettingsChanged { key_path, registry_dir }`，再把 `st.ctx.key` 更新成这把密钥（后面的加水印或检查流程会用到）。
  5. 按 W-COMMON 里的规则跳转。

**S3（222，完成页）**
- 「备份密钥…」：用 `save_file` 选位置，默认文件名 `blindmark-key-backup-YYYYMMDD.key`，然后用 `std::fs::copy` 复制。成功或失败都用一句话提示。
- 「备份登记表…」：用 `pick_folder` 选文件夹，把整个登记表文件夹复制到那里面的 `blindmark-registry-backup-YYYYMMDD` 子文件夹。复制函数写在 jobs.rs 里：`pub fn copy_dir(src, dst) -> Result<usize, UserError>`。
- 只有一个“完成”按钮。

**加水印或检查流程前插入了首次设置时**：完成页（E4、C3）如果发现 `created_key_path` 有值，要在页面里多显示一行“你刚创建了新密钥，请记得备份。”，后面跟一个「备份密钥…」按钮。这一行的文案要加进 ui-copy；按 AGENTS 的规定，在审阅包的“问题”一栏里列出你用的文案，等 Claude 确认。
