# V3-6a 热修复：纯色图片让检测器崩溃

- **基线分支**：最新的 `main`，工作分支 `t-v3-6a`
- **预计**：S
- **这是保护区设计卡**：允许改 `src/wm.rs`、`src/affine.rs`、`src/features.rs`、`src/registry.rs`，范围仅限下文。

## 问题（Claude 已在 Linux 上复现）
1. 检测一张纯色图（全白、单一颜色）时，`wm.rs` 的 `median_filter_nearest` 里 `partial_cmp(..).unwrap()` 遇到 NaN 直接 panic。命令行退出码 101；图形界面里检测线程会崩掉。用户粘贴一张空白截图就会触发。
2. 只把 `unwrap` 去掉还不够：NaN 被排序吞掉后，全白图会得到 `z_sync ≈ 5.76` 这种假分数，离阈值 6.5 很近。

## 修法（照做，补丁 `V3-6a.patch` 已由 Claude 验证）
1. `src/` 里全部 19 处 `a.partial_cmp(b).unwrap()` 换成 `a.total_cmp(b)`。
2. `wm.rs` 新增：
   ```rust
   /// Luma standard deviation below this (grey levels) carries no watermark signal.
   pub const MIN_LUMA_STD: f64 = 1.0;
   pub fn too_flat(y: &Plane) -> bool
   ```
   （总体标准差 < `MIN_LUMA_STD` 返回 true）
3. `wm::detect_axis` 开头：`too_flat` 时直接返回“未找到”，`z_sync = f64::NAN`，其余字段和现有“没有候选周期”的返回值一样。
4. `affine::detect_affine` 开头：`too_flat` 时直接 `return crate::wm::detect_axis(...)`。

可以直接 `git apply V3-6a.patch`，然后补测试。

## 测试（加在 `wm.rs` 的 tests 里）
- 纯色（任意颜色）、全白、全黑 800×600：`detect_luma` 不 panic，`found == false`、`present == false`、`z_sync.is_nan()`
- 纯色 + JPEG 75 往返：同上，不 panic
- 横向渐变 800×600：不 panic，`z_sync` 是有限值（不是 NaN）
- `too_flat`：标准差 0.5 → true，标准差 2.0 → false
