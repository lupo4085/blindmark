## 1. 登记表加一个字段
`registry::Entry` 新增：
```rust
/// SHA-256 of the output file as written to disk (hex). Absent for entries made before v0.3.
#[serde(default, skip_serializing_if = "Option::is_none")]
pub sha256_file: Option<String>,
```
`CopyMeta` 也加同名字段。`register_full` 把它写进条目。
- 普通加水印（`lib::embed_file`）：**先保存文件**，再读回文件字节算 SHA-256，然后调用 `register_full`，`meta` 里只填 `sha256_file`。如果现在的顺序是先登记后保存，要调过来。
- 字段名 `sha256_marked` 的含义不变（像素哈希），不要动。
- 改完用 Python 参考实现检测一次 `tests/golden/marked.png` 并带上新登记表（`--registry`），确认 Python 能读带新字段的登记表。

## 2. distribute.rs（照写签名）
```rust
pub struct Target { pub id: String, pub name: String, pub group_id: Option<String>, pub group_name: Option<String> }

pub struct DistOpts {
    pub root: PathBuf,
    pub per_recipient_dir: bool,
    pub suffix: String,
    pub jpeg_quality: Option<u8>,
    pub strength: f32,
    pub batch_id: String,          // 必填，由调用者生成
    pub tsa: Option<String>,       // None = 不联网
}

pub struct CopyOk { pub file_index: usize, pub recipient_id: String, pub id: u32, pub path: PathBuf, pub psnr: f64, pub sha256_file: String }

pub enum DistProgress<'a> {
    Start { file_index: usize, target: &'a Target },
    Done  { file_index: usize, target: &'a Target, result: &'a Result<CopyOk, anyhow::Error> },
}

pub struct DistOutcome {
    pub copies: Vec<CopyOk>,
    pub failed: Vec<(usize, String, anyhow::Error)>,   // (file_index, recipient_id, 错误)
    pub cancelled: bool,
    pub stamp: Option<Result<timestamp::Stamp, anyhow::Error>>,
}

pub fn batch_id_now() -> String   // "b_YYYYMMDD_HHMMSS_xxxx"，本地时间，xxxx 为 4 位随机十六进制

pub fn distribute(files: &[PathBuf], targets: &[Target], key: &[u8], reg: &mut Registry,
                  o: &DistOpts, cancel: &AtomicBool, on: &mut dyn FnMut(DistProgress)) -> DistOutcome
```
处理顺序：外层按图片，内层按接收人。
- 每生成一份之前检查 `cancel`；为 true 就停，`cancelled = true`。
- 一张图读不出来：这张图对所有接收人都记失败（同一个错误的文字），继续处理下一张图。
- 单份失败（写文件失败等）：记进 `failed`，继续。
- 每一份：`reg.new_id()` → 加水印 → 保存 → **读回文件算 SHA-256** → `register_full`，`CopyMeta` 里 `recipient_id`、`recipient_name`、`group_id`、`group_name`、`batch_id`、`sha256_file` 全部填上。
- 全部结束（包括被停止）后：如果 `o.tsa` 有值并且 `copies` 不为空，就用**已经成功的副本**生成清单并调用 `timestamp::stamp_batch`。清单里的 `recipient_id` 必须填。时间戳失败不影响副本。

**文件夹和文件名**
```rust
pub fn safe_name(name: &str, fallback: &str) -> String
```
1. 把 `\ / : * ? " < > |` 和控制字符换成 `_`；
2. 去掉首尾空白，再去掉末尾的 `.` 和空格；
3. 长度截到 60 个字符；
4. 如果结果（不分大小写，去掉扩展名后）是 `CON PRN AUX NUL COM1–COM9 LPT1–LPT9` 之一，前面加 `_`；
5. 结果为空时用 `fallback`。

`fallback` 传接收人 ID。本批选中的接收人里，如果有两个人的 `safe_name` 相同，这些人的文件夹名（或文件名后缀）一律写成 `{safe_name}_{recipient_id}`。

## 3. jobs.rs
```rust
pub struct DistJob {
    pub files: Vec<PathBuf>,
    pub recipient_ids: Vec<String>,
    pub out_root: PathBuf,
    pub per_recipient_dir: bool,
    pub suffix: String,
    pub strength: f32,
    pub jpeg_quality: Option<u8>,
    pub tsa: Option<String>,
}
pub enum DistEvent {
    Running { done: usize, total: usize, file: String, recipient: String },
    Item { file_index: usize, recipient_id: String, recipient: String, result: Result<DistItemOk, UserError> },
    Stamping,                                   // 开始联网申请时间戳之前发一次
}
pub struct DistItemOk { pub id: u32, pub output: PathBuf }
pub struct DistSummary {
    pub batch_id: String, pub ok: usize, pub failed: usize, pub cancelled: bool,
    pub recipients: usize,                       // 至少成功一份的接收人数，给完成页标题用
    pub stamp: Option<Result<StampOk, UserError>>,
}
pub struct StampOk { pub gen_time_utc: String }

pub fn run_distribute(job: &DistJob, key: &[u8], registry_dir: &Path, cancel: &AtomicBool,
                      on_event: &mut dyn FnMut(DistEvent)) -> Result<DistSummary, UserError>
pub fn retry_stamp(registry_dir: &Path, batch_id: &str, tsa_url: &str) -> Result<StampOk, UserError>
```
- 开始前（任何一份都还没生成）就返回 `Err` 的情况：登记表打不开或不配对（用现有的 `open_registry_for_write`）；接收人名单打不开；某个 `recipient_ids` 找不到或已归档（message：“有接收人已被修改或归档，请回到上一步重新选择。”）；`files` 或 `recipient_ids` 为空。
- `total = files.len() * recipient_ids.len()`。
- 时间戳的 `UserError.message`（照抄）：
  - Network：`暂时没能获取时间戳（无法连接 {host}）。副本已经生成，可以稍后重试。`
  - Rejected：`时间戳服务拒绝了这次请求（状态 {status}）。副本已经生成，可以稍后重试。`
  - Mismatch / Malformed：`时间戳服务返回的数据和这次请求对不上，已作废。副本已经生成，可以稍后重试。`
  - `detail` 放原始信息。
- 单份失败的 message 用现有的 `classify`。

## 4. 命令行
`embed --to` 分支改为调用 `jobs::run_distribute`（`--to` 的人名先用 `recipient_by_name_or_create` 换成 ID）。每份输出一行 JSON：`{"id","recipient","recipient_id","output","sha256_file"}`；最后输出一行 `{"batch_id","ok","failed","stamp":"ok"|"failed"|null}`。Ctrl+C 不用处理。
