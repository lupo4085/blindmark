# V3-2 可信时间戳：改成真正可信，并且默认不联网

- **基线分支**：`t-v3-1` 合并后的 `main`，工作分支 `t-v3-2`
- **预计**：M
- **范围**：`src/timestamp.rs`、`src/bin/cli.rs`（只改 `stamp` 子命令和 `embed` 的时间戳参数）、`src/distribute.rs`（只跟着改字段名 `sha256_marked` → `sha256_file`，让它能编译；值暂时不变，V3-4 再改）。**允许的联网代码只有 `timestamp.rs` 里的 `post_tsa`，不许在别处新增。**
- **修的问题**：现状审阅 A1（默认开启）、A2（成功判定是错的）

## 1. 默认不联网
- 命令行：删掉 `--no-timestamp`，改成 `--timestamp`（不加就不联网）和 `--tsa <URL>`（默认 `DEFAULT_TSA`）。
- `timestamp.rs` 自己不读任何设置，是否联网完全由调用者传 `Option<&str>` 决定。

## 2. 请求加上 nonce
`TimeStampReq` 的字段顺序是 version、messageImprint、（reqPolicy 不用）、nonce、certReq。
- nonce 是 8 个随机字节（`getrandom`），然后 `b[0] = (b[0] & 0x7F) | 0x40`。这样编码后正好 8 字节、是正数、符合 DER 最短编码。
- 编码为 `INTEGER`（tag 0x02，长度 8）。
- `build_request` 改为 `pub fn build_request(digest: &[u8; 32], nonce: &[u8; 8]) -> Vec<u8>`，方便测试用固定 nonce。

## 3. 解析响应，严格判定成功
新增一个最小的 DER 读取器（只在本文件内，不加依赖）：
```rust
/// 读一个 TLV。只支持单字节 tag；长度支持短格式和 0x81–0x84 长格式；遇到 0x80（不定长）报错。
fn read_tlv(buf: &[u8]) -> Result<(u8, &[u8], &[u8])>   // (tag, body, rest)
```
任何越界都返回 `Err`，**绝不 panic**。

解析路径（RFC 3161 和 RFC 5652）：
```
TimeStampResp  SEQUENCE
  status       SEQUENCE { status INTEGER, ... }      ← 只接受 0 (granted) 和 1 (grantedWithMods)
  token        SEQUENCE (ContentInfo)
    contentType  OID 1.2.840.113549.1.7.2 (signedData)
    [0] (tag 0xA0)
      SignedData SEQUENCE
        version INTEGER
        digestAlgorithms SET
        encapContentInfo SEQUENCE
          eContentType OID 1.2.840.113549.1.9.16.1.4 (TSTInfo)
          [0] (0xA0) → OCTET STRING (0x04) → TSTInfo 的 DER
TSTInfo SEQUENCE
  version INTEGER
  policy OID
  messageImprint SEQUENCE { alg SEQUENCE, hashedMessage OCTET STRING }
  serialNumber INTEGER
  genTime GeneralizedTime (tag 0x18)
  然后依次是可选的 accuracy (SEQUENCE 0x30)、ordering (BOOLEAN 0x01)、nonce (INTEGER 0x02)、[0]、[1]
```
判定规则，**全部满足才算 ok**：
1. status 是 0 或 1；
2. hashedMessage 等于本地算出的 32 字节摘要；
3. TSTInfo 里有 nonce，并且和请求时发的完全一致（逐字节比较 INTEGER 的内容）。

成功时取出 genTime（格式 `YYYYMMDDHHMMSS[.小数]Z`），转成 RFC 3339 存起来；serialNumber 存成十六进制。

**不验证 TSA 的签名。** 签名留在 `response.tsr` 里，任何人都可以用 OpenSSL 独立核验（命令写进 `timestamps/README.txt`，见第 5 节）。

## 4. 数据结构（照写）
```rust
pub struct StampRecord {
    pub tsa_url: String,
    pub requested_utc: String,
    pub ok: bool,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub status: Option<u32>,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub gen_time_utc: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub serial_hex: Option<String>,
    pub nonce_hex: String,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub error: Option<StampError>,
    pub digest: String,
}

#[derive(Clone, Debug, Serialize, Deserialize, PartialEq)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum StampError {
    Network { host: String, detail: String },   // 连不上、超时、HTTP 非 200
    Rejected { status: u32 },                    // status 不是 0/1
    Mismatch { detail: String },                 // 摘要或 nonce 对不上，或缺 nonce
    Malformed { detail: String },                // 解析失败
}

pub struct Stamp { pub dir: PathBuf, pub batch_id: String, pub record: StampRecord }
```
`Manifest` 和 `ManifestCopy` 里的 `sha256_marked` **改名为 `sha256_file`**，含义是“写到磁盘上的文件的 SHA-256”。`MANIFEST_FORMAT` 保持 `blindmark/batch/v1`（alpha 的清单从未正式发布过）。真正填这个值是 V3-4 的事，这张卡只改名。

## 5. 函数（照写签名）
```rust
pub fn stamp_batch(registry_dir: &Path, manifest: &Manifest, tsa_url: &str) -> Result<Stamp>
pub fn retry_batch(registry_dir: &Path, batch_id: &str, tsa_url: &str) -> Result<Stamp>
pub fn list_batches(registry_dir: &Path) -> Result<Vec<(String, Option<StampRecord>)>>  // 按 batch_id 排序
pub fn host_of(url: &str) -> String   // "https://freetsa.org/tsr" → "freetsa.org"，给界面文案用
```
- `stamp_batch`：照旧写 `manifest.json`、`manifest.sha256`、`request.tsq`，联网，写 `response.tsr`（只要收到了字节就写，即使判定失败也写，方便排查）和 `tsa.json`。**联网或判定失败不返回 Err**，而是返回 `ok: false` 的记录；只有写文件失败才返回 Err。
- `retry_batch`：读已有的 `manifest.json` 原始字节（**不重新序列化**，摘要必须不变），用新 nonce 重新请求，覆盖 `request.tsq`、`response.tsr`、`tsa.json`。
- 第一次写 `timestamps/` 目录时，同时写一个 `timestamps/README.txt`，内容照抄：
  ```
  每个子文件夹是一批分发的副本。
  manifest.json   这批副本的清单（编号、接收人、文件的 SHA-256）
  response.tsr    时间戳服务签名的回执，证明清单在 tsa.json 里的 gen_time_utc 之前就已存在

  独立核验（需要 OpenSSL，以及时间戳服务的 CA 证书和 TSA 证书）：
  openssl ts -verify -data manifest.json -in response.tsr -CAfile cacert.pem -untrusted tsa.crt
  ```
- `post_tsa`：用 `ureq::AgentBuilder` 设 20 秒超时。

## 7. 测试（都在 `timestamp.rs` 的 tests 里，不联网）
在测试里写一个小工具，用 `tlv()` 拼出假的 `TimeStampResp`。至少覆盖：
- 状态 0、摘要和 nonce 都对 → ok，genTime 正确转换（例如 `20261109183000Z` → `2026-11-09T18:30:00Z`，带小数的 `20261109183000.5Z` 也能解析）
- 状态 2 → `Rejected { status: 2 }`
- 摘要不对 → `Mismatch`
- nonce 不对、或者 TSTInfo 里没有 nonce → `Mismatch`
- 响应截断到一半 → `Malformed`，不 panic
- 用固定种子生成 1000 段随机字节喂给解析函数，全部返回 Err，不 panic
- `build_request` 带 nonce 后的字节结构（在原有测试上改）
- `retry_batch` 读回的摘要和第一次一致（不联网：把 `post_tsa` 换成可注入的函数，或者测试只调用“解析 + 写记录”的内部函数，二选一，在审阅包里说明选了哪种）
