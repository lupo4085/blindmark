## 背景
现在“found”的判定是：同步分数 `z_sync ≥ 6.5`（严格模式 7.5），并且 CRC 通过、或者在登记表里匹配上。6.5 是经验值。v0.3 要在 README 里写出“未加水印的图片被误判为‘找到你的水印’的概率不超过 10⁻ⁿ”，这个 n 必须有数据支撑。

`z_sync` 是在很多候选周期和仿射候选里取最大值得到的，**不服从标准正态分布**，所以不能直接查正态表，要实测它在未加水印图片上的分布。

## 数据
- **负样本（未加水印）**：Lupo 准备一个文件夹，至少 150 张**从没加过水印**的图片，尽量混合：手机照片、插画、截图、纯色或大面积平涂的图、文字很多的图。另外由程序生成 30 张合成图（纯色、渐变、高斯噪声、棋盘格、随机文字块各 6 张，固定种子）。
- **正样本（加了水印）**：从负样本里按文件名排序取前 40 张，用随机密钥和随机编号加水印。
- 所有图片先缩放到长边不超过 1600 像素（`INTER_AREA` 同类的缩小方式，用 `imgproc` 里已有的函数），模拟网上常见的尺寸，也让总耗时可控。

## 程序：`examples/calibrate.rs`
```
cargo run --release --example calibrate -- --images <DIR> --out calib.csv [--keys 10] [--registry-size 1000] [--resume]
```
对每张负样本图片，生成 3 个版本：`orig`、`jpeg75`、`half`（缩小一半）。对每个版本、每把密钥（`--keys` 把，用固定种子 `0xCA11B` 生成，可复现）：
1. 用这把密钥生成 `--registry-size` 个随机编号，构造 `KnownIds`。
2. 调用 `wm::detect_luma(&y, key, Some(&known), f64::NEG_INFINITY)`。阈值传负无穷，是为了让每一张都走完 CRC 和登记表匹配两步，拿到完整的原始分数。
3. 记一行。

正样本：每张图 × 1 把密钥，版本是 `orig`、`jpeg75`、`half`、`crop50`（居中裁一半面积），同样记录。

CSV 列（照写，顺序不变）：
```
kind,image,variant,key_index,w,h,z_sync,method,z_id,seconds
```
- `kind` 是 `neg` 或 `pos`；`method` 是 `crc`、`registry` 或空；`z_id` 没有就空着。
- `--resume`：读已有的 CSV，跳过已经算过的 `(kind,image,variant,key_index)`。每算完一行就追加写入并 flush，中途关机不丢数据。
- 标准错误每 50 行打印一次进度和预计剩余时间。

## 报告：`python/calib_report.py`
```
python python/calib_report.py calib.csv > docs/calibration.md
```
只用 numpy 和标准库（不要 scipy、不要画图库）。输出 Markdown，内容：
1. 样本数：负样本多少行（按 variant 分开），正样本多少行。
2. 负样本 `z_sync` 的分位数：50%、90%、99%、99.9%、最大值，按 variant 分开和合并各一行。
3. 对阈值 t = 4.0, 4.5, …, 9.0：
   - 负样本中 `z_sync ≥ t` 的实测比例
   - Gumbel 拟合的外推概率：用合并后的负样本 `z_sync` 按矩估计 `β = s·√6/π`，`μ = mean − 0.5772·β`，`P(z ≥ t) = 1 − exp(−exp(−(t − μ)/β))`
   - 正样本中 `z_sync ≥ t` 的比例（按 variant 分开），也就是这个阈值下还能保留多少检出
4. 负样本里 `method` 非空的行数（在负无穷阈值下 CRC 碰巧通过、或登记表碰巧匹配的次数），以及对应的 `z_sync` 值。理论上 CRC 碰巧通过的概率是 2⁻¹⁶。
5. 一段“如何解读”，照抄：
   > 一张未加水印的图片被判为“找到你的水印”，需要同时满足两件事：同步分数超过阈值，以及 CRC 碰巧通过（概率 2⁻¹⁶）或登记表碰巧匹配（设计值 10⁻⁶）。所以整体误报率约等于第 3 节的外推概率 × (2⁻¹⁶ + 10⁻⁶)。
