# 界面文案规范 v1（2026-11-07）

适用于整个程序，《docs/specs/wizard.md》里的文案也按本规范统一。实现时**只能照抄本文和规格里的文案**，需要新增文案时先在审阅包里提问。

## 一、用语表（全程序统一）

| 统一用 | 不再使用 | 说明 |
|---|---|---|
| 你 | 您、本人 | 语气友好直接，和主窗口一致 |
| 加水印 | 嵌入水印、添加水印 | 和主窗口选项卡名一致 |
| 检查（向导里）／检测（选项卡名） | 读取水印、核对 | |
| 编号 | ID、标识 | 显示格式保持 `0x1a2b3c4d` |
| 副本 | 拷贝、复制品 | |
| 接收人 | 收件人、对象 | |
| 备注 | 渠道备注、渠道 | 界面上统一写“备注”；数据字段名 `channel` 不变 |
| 选择 | 选取、选定 | |
| 停止 | 中止 | |
| 使用这把密钥／移除（不删除文件） | 载入、卸载 | |
| 密钥指纹 | 指纹 | 第一次出现时解释：用来核对是不是同一把密钥 |
| BlindMark | blindmark（作为显示名称时） | 程序名称一律写 BlindMark；命令名和文件名仍然用小写 blindmark |

**写法规则**
- 句子用中文全角标点。按钮文字不加句号。打开新对话框的按钮以“…”结尾。
- 按钮写成“动词 + 宾语”。
- 错误提示分三层：发生了什么 → 为什么（可省略）→ 现在可以怎么做。技术细节放进“详细信息”，或者只写进日志。
- 少用“错误”“失败”。部分成功时写“已完成 8 张，2 张没有处理”。
- 不写“请单击‘下一步’继续”这一类重复按钮作用的话。
- 正文里不出现 PSNR、z 值、阈值、仿射、错切等术语。它们只能出现在“详细信息”或“技术详情”里。

## 二、UserError 的中文提示

| 情况 | message |
|---|---|
| 登记表和密钥不配对 | 这个登记表属于另一把密钥（密钥指纹 {fp}），不能和当前密钥一起使用。请换一个登记表文件夹，或改用对应的密钥。 |
| 登记表打不开 | 无法打开登记表 {dir}。请检查这个文件夹是否存在、是否可以写入。 |
| 图片打不开 | 无法打开 {name}：文件可能已损坏，或者不是支持的图片格式。 |
| 输出文件夹不可写 | 无法保存到 {dir}。请换一个文件夹，或检查这个文件夹是否只读。 |
| 密钥文件无效 | {name} 不是 BlindMark 的密钥文件。 |
| 时间戳服务连不上 | 暂时没能获取时间戳（无法连接 {host}）。副本已经生成，可以稍后在登记表中重试。 |
| 其他意外错误 | 处理 {name} 时出了问题。点“详细信息”可以查看原因。 |
| 向导内部意外（panic） | 向导遇到了意外问题，已经关闭。你的图片、密钥和登记表都没有受影响。 |

## 三、向导文案（逐页）

### 欢迎页
- 标题：欢迎使用 BlindMark
- 副标题：给图片加上看不见的水印，证明图片是你的
- 正文：
  > BlindMark 会在图片里加入肉眼看不见的编号。图片被转发、截图或压缩后，通常仍然能读出这个编号，用来证明图片是你的，并查出是从哪一份副本流出去的。
  >
  > 这个向导会带你完成：
  > · 首次设置：创建密钥、选择登记表的位置
  > · 给图片加水印
  > · 分发给多人：每人一份独立编号的副本
  > · 检查可疑图片
  >
  > 所有处理都在你的电脑上完成，图片不会上传。
- 复选框：启动时显示此向导

### 选择任务页
- 标题：选择要做的事
- 副标题：以后随时可以按 F1 回到这里。
- 单选项（粗体标题 + 灰色说明）：
  1. 完成首次设置 —— 创建密钥，并选择登记表的保存位置。（已有密钥时改为：**更换密钥或登记表** —— 改用另一把密钥，或换一个登记表文件夹。）
  2. 给图片加水印 —— 为每张图片生成一份带编号的副本，编号会记进登记表。
  3. 分发给多人 —— 给每位接收人各生成一份编号不同的副本，泄露后能查出是谁。
  4. 检查可疑图片 —— 看图片里有没有你的水印，以及它是哪一份副本。

### 临时占位页（W-1 到 W-4 期间使用，完成对应流程后删除）
- 标题：这一步还在制作中
- 副标题：（空）

  - 检查可疑图片 → 去处：“检测”选项卡
- 按钮：只有「< 上一步」和「完成」

- 副标题：只有用这把密钥，才能读出你加的水印

- 页面内错误：
  - 请先新建一把密钥，或选择已有的密钥文件。
  - {name} 不是 BlindMark 的密钥文件。
  - 无法在 {dir} 创建密钥。请换一个位置。

### S2 登记表
- 标题：选择登记表的保存位置
- 副标题：登记表记录每个编号对应哪张原图、发给了谁

- 标签：位置；按钮「浏览…」
- 状态行（三选一）：

- 标题：设置这批图片的水印
- 副标题：这些选项只用于这一次，不会改变你的默认设置
- 备注（可选）：输入框内的灰色提示为“例如：发到微博、给甲方的终稿”

  - {name}：没有找到你的水印

- 教学提示：以后可以在“检测”选项卡里直接按 Ctrl+V 粘贴截图。 按钮：「转到“检测”选项卡」

### D2 选择接收人（补充，取代第三节 D2 的按钮行）

- 已归档的人：灰色显示，姓名后加“（已归档）”，不能勾选

- 空状态（所选分组里没有人）：这个分组里还没有人。
- 编辑接收人对话框：标题“编辑接收人”；字段同“新建接收人”；按钮「保存」「取消」

- 归档确认框：要归档“{name}”吗？\n\n归档后，这个人不会再出现在名单里。已经发给他的副本和登记记录都会保留，检测时照常显示他的名字。 按钮：「归档」「取消」
- 接收人名单打不开时（页面内红字）：接收人名单（recipients.json）打不开：文件可能已损坏。
- 汇总行、页面内错误：沿用第三节

### D3 提交说明（正文最后一行，灰色）
- 点击“{按钮文字}”后开始生成副本，已完成的部分无法通过“上一步”撤销。

### D4 进度页
- 进度文字：正在处理 {file} → {recipient}（{done}/{total}）…
- 申请时间戳时：正在申请可信时间戳…

### D5 完成页（取代第三节 D5 的标题和时间戳行）

- 结果列：接收人、图片、结果。成功：编号 {id}，保存为 {output}；没完成：{message}
- 时间戳行（没勾选时整行不显示）：
  - 成功：时间戳已获取（{time}）。 — {time} 用本地时间，格式 `YYYY-MM-DD HH:MM`
  - 失败：{message}（来自 V3-4 的 UserError） 旁边按钮：「重试」

- 教学提示：以后可以在“加水印”选项卡里选好图片，点“分发给多人…”直接完成。 按钮：「转到“加水印”选项卡」

### 助记词
- 设置页“密钥”一组新增按钮：「显示助记词…」「用助记词恢复…」
- 显示前的确认框（只在设置页弹，向导 S3 不弹）：助记词会显示在屏幕上。请确认周围没有人在看，也没有在录屏或共享屏幕。 按钮：「显示」「取消」
- 显示助记词对话框：
  - 标题：密钥助记词
  - 第一行（加粗）：按顺序抄下这 24 个词
  - 说明：凭这 24 个词，可以在任何电脑上恢复这把密钥（密钥指纹 {fp}）。任何人拿到它们，就等于拿到了你的密钥。请抄在纸上放好，不要截图，也不要发给别人。
  - 正文：4 列 × 6 行，每格“{序号}. {词}”，等宽字体，按列排（第一列是 1–6）
  - 按钮：「我已抄好」。**不提供“复制”按钮**
  - 密钥不是标准长度时不打开对话框，改为提示：这把密钥不是标准长度，不能生成助记词。请直接备份密钥文件。
- 恢复对话框：
  - 标题：用助记词恢复密钥
  - 说明：按顺序输入 24 个词，用空格或换行隔开。从别处粘贴带序号的文本也可以。
  - 多行输入框，下方实时计数：已输入 {n} / 24 个词
  - 错误（红字，在计数下方）：沿用 V3-5 的 UserError 原文
  - 按钮：「恢复」「取消」
  - 从设置页恢复成功后，弹“另存为”，默认文件名 `blindmark.key`，默认文件夹是程序数据文件夹；保存后状态栏：已恢复密钥（密钥指纹 {fp}）
- 向导 S1 新增第三个单选项：用助记词恢复密钥 —— 旁边按钮「输入助记词…」；识别成功后下方显示：已识别，密钥指纹 {fp}。没输入就点下一步时（页面内红字）：请先输入助记词。
- 向导 S3 新增按钮：「抄写助记词…」（放在「备份密钥…」右边）；提示行改为：最稳妥的做法是两样都做：备份密钥文件，并把助记词抄在纸上。以后可以在主窗口的“设置”选项卡里随时做这两件事。
