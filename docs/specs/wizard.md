# 向导设计规格（2026-11-07，合并 v1 和 v1.1）

- 依据：微软《向导》设计准则，经典 Win32 向导样式
- 文案：一律以 `ui-copy.md` 第三节为准，本文不再重复
- 替代：现有的 `src/win/wizard.rs`，**整个重写**

## 0. 必须根除的致命缺陷
**关闭向导时整个程序一起退出。** 原因是 `wizard::open` 里先 `Box::new` 出 `boxed`，又对同一个对象 `Box::from_raw(raw)` 得到 `done`。函数返回时两个 Box 都会释放，同一块内存被释放两次，Windows 检测到堆损坏后结束进程。

新实现的强制要求：
1. 向导状态的所有权只有一份：用 `Box::into_raw` 交出去，`PropertySheetW` 返回后用 `Box::from_raw` 收回，且只收回一次。指针放在 `PROPSHEETPAGEW.lParam` 里，`WM_INITDIALOG` 时存进 `GWLP_USERDATA`。**不用 thread_local 存裸指针。**
2. 每个页面的过程函数都用 `catch_unwind` 包起来。发生 panic 时：记日志 → 用 `ui-copy` 里的“其他意外错误”提示用户 → 关闭向导。
3. 验收时用五种方式关闭向导：取消、✕、Esc、完成、关闭。每种方式关闭后主窗口都必须还在。

## 1. 外壳（保持现有外观）
- 保留现在的 `PSH_WIZARD_LITE`、各页在 `WM_ERASEBKGND` 里自绘的左侧水印条和标题栏，`paint_banner` 和两张 bmp 也保留。窗口标题仍是“BlindMark 向导”。
- 页面模板统一用 317×193 DLU。D2 如果放不下，**所有页一起**放大，不允许只放大某一页。
- 一起修掉 alpha.1 的已知问题：竖排文字底部被裁约 10px、窄窗口下提示折行、高对比度主题下显示不正确。在 100%、125%、150%、200% 缩放下各截一张图核对。
- 欢迎页和完成页用**外页样式**（正文在水印条右侧）；其余页用**内页样式**。

## 2. 流程
```
欢迎页 → 选择任务 ─┬─ 首次设置：S1 密钥 → S2 登记表[提交] → S3 完成页
                    ├─ 加水印：  E1 选图 → E2 选项[提交] → E3 进度 → E4 完成页
                    ├─ 分发：    D1 选图 → D2 接收人 → D3 选项[提交] → D4 进度 → D5 完成页
                    └─ 检查：    C1 选图[提交] → C2 进度 → C3 完成页
```
- **没有密钥时**选了加水印、分发或检查：先插入 S1、S2，S2 的提交按钮文字写“保存并继续”，跳过 S3，然后进入原先选择的任务。原本 S3 里的备份按钮挪到这个任务的完成页上。
- **分支只在“选择任务”这一处**，进入任务后是直线流程，不再分叉。
- **跳转**：一律在 `PSN_WIZNEXT` / `PSN_WIZBACK` 里把 `DWLP_MSGRESULT` 设成目标页的资源 ID。状态里维护一个已访问页面的栈，“上一步”按这个栈往回走。**禁止**再用“`PSN_SETACTIVE` 返回 -1”的方式跳过页面。
- **步骤提示**：内页副标题前面加“第 X 步，共 Y 步 · ”。Y 从选择任务那一页起算，中途不变。
- **上一步**：提交之前，返回时不清空已填内容，再点下一步时原样保留。进度页和完成页不显示“上一步”。
- **取消**：提交之前直接关闭，不弹确认。进度页上的“取消”按钮作用是停止：先问一次，用户确认后等当前这一张处理完再停，然后进入完成页，标题显示“已停止”。
- **提交页按钮**：先用 `PSM_SETNEXTTEXT` 把按钮文字改成提交文案，比如“开始加水印”。如果 LITE 模式下这样改不生效，就保留“下一步 >”，并在页面正文最后加一行：点击“下一步”后开始{动作}，已完成的部分无法通过“上一步”撤销。
- **完成页**只有“完成”一个按钮。

## 3. 启动时弹出
- `Settings` 新增 `show_start_wizard: bool`，默认 `true`。首次运行判断不再依赖“settings.json 是否存在”。
- 欢迎页底部有复选框“启动时显示此向导”。**无论向导以什么方式关闭**，都把这个复选框的状态立刻写入设置。
- 菜单：帮助 → 开始使用…（F1）。去掉 Ctrl+W 和“文件 → 使用向导…”。
- 如果关掉了启动向导，并且还没有密钥：不自动弹出向导，只在状态栏显示提示（文案见 `ui-copy`）。

## 4. 各页行为
（所有文案见 `ui-copy.md`）

**选择任务**：默认选项为：没有密钥时选第 1 项，已有密钥时选第 2 项。

**S1**：这一页**不往磁盘写任何东西**，只记下用户的选择。默认选“新建”，路径为 `%APPDATA%\blindmark\blindmark.key`。如果目标位置已经有密钥，就询问是否直接使用它，**绝不覆盖**。如果用户选“使用已有”：显示路径和密钥指纹。文件无效时在页面内显示红字提示，不弹窗。

**S2**：默认路径为 `%APPDATA%\blindmark\registry`。路径一变就刷新状态行（新的／匹配，共 N 条／属于另一把密钥）。刷新状态行**不能创建文件夹**，所以只能读，不能调用 `Registry::open`；需要的话在 `jobs.rs` 里加一个只读的检查函数。提交时依次：按需生成密钥 → 用 `check_key` 校验登记表 → 把 `key_path` 和 `registry_dir` 交回 App，由 App 保存。不匹配时按钮仍然可以点，点了以后在页面内说明原因，并停在这一页。

**S3**：「备份密钥…」打开“另存为”对话框，默认文件名 `blindmark-key-backup-YYYYMMDD.key`，内容就是复制一份密钥文件。

**E1 / D1 / C1**：可以拖入图片。如果主窗口“加水印”列表里已经有图，就预先填进来；C1 不预填。列表为空时在页面内提示。C1 支持粘贴剪贴板里的截图。

**E2**：默认值取自全局设置，**改动不写回全局设置**。强度滑块的范围和主窗口一致（15–40，也就是 1.5–4.0）。选 PNG 时质量不可选。

**D2**：
- 左侧分组树。选中一级分组时，右边同时显示它下面子分组里的人。
- 接收人列表带复选框，**默认全不勾**。切换分组、新建接收人之后，已勾选的状态都保留。
- 新建接收人、新建分组各用一个独立的小对话框。新建的接收人自动勾上，并归到当前选中的分组。
- 汇总行实时更新。
- 依赖 alpha 分支的 `recipients.rs`。

**D3**：可信时间戳**默认不勾**。

**进度页**：用确定进度的进度条。全部成功时自动进入完成页；有失败时也进入完成页，完成页里列出失败的几张。

**完成页**：
- “在登记表中查看”：关闭向导，切到登记表页，并选中本次生成的编号。
- “转到某选项卡”：关闭向导，切到对应选项卡。

**C 流程**：使用全局设置里的检测选项（`cfg.detect_options()`），**不设检测选项页**。

## 5. 和主窗口的接口
```rust
pub enum WizardOutcome {
    Closed,
    SettingsChanged { key_path: PathBuf, registry_dir: PathBuf },
    ShowTab(usize),
    ShowInRegistry(Vec<u32>),
}
pub struct WizardContext { pub cfg: Settings, pub key: Option<Vec<u8>>, pub embed_files: Vec<PathBuf> }
pub fn run(owner: HWND, ctx: WizardContext) -> WizardOutcome;
```
- 向导**不写全局设置**。只有一个例外：`show_start_wizard`。
- 后台任务一律调用 `blindmark::jobs`（见 W-0）。
- 向导返回后，App 总是调用 `load_key_and_registry` 重新加载密钥和登记表，再处理返回的 Outcome。

## 6. 验收（截图 + 走查）
**截图**：每页一张。选择任务页截“有密钥”“没密钥”两种状态；D2 截空名册、已勾选、刚新建了接收人三种状态；C3 截四种结果。

**走查**：
1. 删除 settings.json 后启动 → 向导自动弹出 → 走完首次设置 → 备份密钥 → 完成 → 主窗口还在，并且已经载入了新密钥。
2. 加水印 2 张 → 在完成页点“在登记表中查看” → 登记表页选中了这 2 条。
3. 分发：在向导里新建 2 位接收人，勾选他们 → 生成 4 份 → 在“检测”页检查其中一份 → 能看到接收人。
4. 取消勾选“启动时显示此向导”后按 ✕ 关闭 → 重新启动程序不再弹出向导 → 按 F1 能打开。
5. 用五种方式关闭向导，主窗口都还在。
6. 在 E2 填好备注 → 上一步 → 下一步 → 备注还在。
7. 进度页点停止 → 完成页显示已完成的部分 → 登记表里有这几条。
8. 选一把和登记表不配对的密钥 → S2 显示红字，并且无法继续。

## 7. 任务卡顺序
HF-1（热修复）→ W-0（jobs.rs）→ W-1（外壳、欢迎页、选择任务页、启动弹出）→ W-2（S1–S3）→ W-3（E1–E4）→ W-4（C1–C3）→ W-5（D1–D5，要先等 alpha 合并完、并修完 D 系列问题）

## 8. v0.3 补充（2026-11-09）
- **从主窗口进入分发**：`WizardContext` 新增 `start_task: Option<Task>`。为 `Some(Distribute)` 时跳过欢迎页和选择任务页，直接打开 D1（没有密钥时打开 S1，步骤数按“前面插入了 S1、S2”计算）。从这里进来时 D1 的“上一步”不显示。
- **页面 ID**：D1 250、D2 251、D3 252、D4 253、D5 254。D5 是完成页（外页样式）。
- **步骤提示**：分发 D1=1、D2=2、D3=3、D4=4，y=4；前面插入 S1、S2 时 y=6。
- **D2 的接收人管理**：见 ui-copy 第五节。接收人名单在 D2 里直接改（新建、编辑、归档、恢复、新建分组、重命名分组），改动立刻写入 `recipients.json`，不等向导结束。
- **D3 默认值**：保存位置默认取 `cfg.out_dir`，为空时取第一张图所在文件夹；每人一个文件夹默认选中；格式和强度默认取全局设置；时间戳**默认不勾**，并且不记住上次的选择。
- **时间戳服务地址**：`Settings.tsa_url`，默认 `blindmark::timestamp::DEFAULT_TSA`，界面上不提供修改入口（高级用户可以改 settings.json）。
- **S1 助记词恢复**、**S3 抄写助记词**：见 ui-copy 第五节。S1 仍然不写磁盘，恢复出的密钥字节先放在 `St` 里，到 S2 提交时用 `jobs::restore_key_file` 写到 S1 选定的位置。
