# 架构说明（2026-11-07，2026-11-21 修订）

## 模块
| 模块 | 作用 | 谁能改 |
|---|---|---|
| `src/keys.rs` `src/wm.rs` `src/affine.rs` `src/features.rs` `src/imgproc.rs` | 水印格式 blindmark/v1 和检测算法 | 只能按 Claude 的设计卡改 |
| `src/registry.rs` | 登记表：`registry.json` + `meta.json` + 缩略图 | 字段改动需要设计卡 |
| `src/recipients.rs` `src/distribute.rs` `src/timestamp.rs` | 接收人簿、分发、可信时间戳 | 按任务卡；文件格式改动需要设计卡 |
| `src/jobs.rs` | **后台任务的唯一实现**：加水印、分发、检测 | 按任务卡 |
| `src/lib.rs` | `embed_file`、`detect_image_opts`、`Report` | 按任务卡 |
| `src/bin/cli.rs` | 命令行 | 按任务卡 |
| `src/win/*` | Win32 界面，只负责显示和收集输入 | 按任务卡 |

## 状态归属（最重要的规则）
1. **设置**：`App.cfg` 是唯一的内存副本。其他窗口（首次设置向导、对话框）拿到的是副本，改动通过返回值交回 App，由 App 写入 `settings.json`。
2. **登记表**：`App.reg` 只用于显示。后台任务在自己的线程里重新打开登记表，并在里面写入。**任何后台任务写完以后，App 都必须调用 `reload_registry()`。**
3. **密钥和登记表必须配对**：凡是要写登记表的任务，都要先调用 `check_key`。这一步统一在 `jobs.rs` 里做，界面代码不要自己重复做。
4. **界面不直接调用 `embed_file`、`detect_image*`、`distribute`**，一律通过 `jobs.rs` 调用。这样图形界面和命令行用的是同一份逻辑，不会再出现两边行为不一致。

## 错误
- `jobs.rs` 对外只返回 `UserError { message, detail }`。
- `message` 是给用户看的中文一句话，写法按 `docs/specs/ui.md` 第 0 节。
- `detail` 是原始错误，只在点“详细信息”时显示，或者写进日志。

## 窗口和线程
- 后台线程通过 `PostMessage`、channel 加定时器把消息交回界面线程。界面控件只能在界面线程里操作。
- 模态窗口关闭时，必须重新启用它的父窗口。对话框正在执行任务时不能直接销毁，必须先问用户，或者先停下任务。

## v0.3 新增规则（2026-11-09）
1. **联网**：整个程序只有 `timestamp::post_tsa` 一处联网。只有用户在这一批加水印或分发上**主动勾选**时间戳（命令行是 `--timestamp`），或者主动点“重试”时才会调用。默认值永远是不联网，也不记住上次的选择。
2. **接收人名单** `recipients.json` 放在登记表文件夹里，只通过 `recipients::Book` 的方法读写。加水印选项卡的接收人栏在界面线程里直接改名单（文件很小）；后台分发任务只在开始时读一次。登记表条目里的接收人姓名是**分发当时的快照**，以后改名不影响已有记录，检测结果显示快照。
3. **助记词**：只在内存里出现。不写日志、不写任何文件、不进剪贴板。界面上显示助记词的控件不允许选中复制。
4. **哈希**：登记表的 `sha256_file` 和时间戳清单的 `sha256_file`，都是写到磁盘以后的文件字节的 SHA-256，任何人拿到文件都能复核。`sha256_marked` 是像素哈希，含义不变。
5. **读不回就算没完成**：加水印和分发保存以后马上读回自检。读不回的删掉输出、不登记，返回 `WatermarkNotReadable`；偏弱的照常保存登记，但要标出来。界面和命令行都不能把读不回的算成成功。
6. **已有文件绝不覆盖**：所有输出都经过 `unique_output_path`。
7. **测试数据**：环境变量 `BLINDMARK_DATA_DIR` 指定设置、密钥、登记表所在的文件夹，主窗口标题会标出“测试数据”。走查和演示一律用它，不碰真实数据。
